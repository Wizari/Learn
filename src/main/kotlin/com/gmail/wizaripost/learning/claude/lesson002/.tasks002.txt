Наследование

В Kotlin классы по умолчанию final — нельзя унаследоваться, пока явно не разрешишь через open:

kotlin
open class Animal(val name: String) {
    open fun makeSound(): String = "..."
}

class Dog(name: String) : Animal(name) {
    override fun makeSound(): String = "Гав!"
}

Обрати внимание на две вещи:

open нужен и на классе, и на методе, который хочешь переопределять
override обязателен — без него не скомпилируется

Это осознанное решение дизайна Kotlin: наследование — это не то, что должно быть возможно "по умолчанию", а то, что автор класса явно разрешает.

Интерфейсы
kotlin
interface Movable {
    fun move(): String

    fun describe(): String = "Я умею двигаться" // можно дать реализацию по умолчанию
}

class Dog(name: String) : Animal(name), Movable {
    override fun move(): String = "$name бежит"
}

Ключевое отличие от абстрактного класса: класс может реализовать много интерфейсов, но унаследоваться только от одного класса. Интерфейс — это контракт "что уметь делать", класс — это "чем являться".

Abstract class

Промежуточный вариант — когда хочешь и общую реализацию дать, и заставить наследников что-то реализовать самим:

kotlin
abstract class Shape {
    abstract fun area(): Double

    fun describe(): String = "Площадь фигуры: ${area()}"  // не abstract — есть реализация
}

class Circle(val radius: Double) : Shape() {
    override fun area(): Double = Math.PI * radius * radius
}

Abstract class нельзя создать напрямую (Shape() — ошибка), только через наследников.
